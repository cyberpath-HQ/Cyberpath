# Markdown for Agents

Agents get cleaner, cheaper context when a site returns markdown instead of a full HTML
page. This repository publishes a markdown variant for **every** page and serves it through
a small Cloudflare Worker, because the site itself is a static Astro build on GitHub Pages
and GitHub Pages cannot inspect the `Accept` header.

```
agent   ──Accept: text/markdown──▶ Cloudflare Worker ──GET /<path>/index.md──▶ GitHub Pages
browser ──Accept: text/html───────▶ Cloudflare Worker ──GET /<path>/─────────▶ GitHub Pages
```

## What the build produces

| URL | Markdown variant |
| --- | --- |
| `/` | `/index.md` (redirect document, mirrors the 303 to `/it/`) |
| `/en/`, `/it/` | `/en/index.md`, `/it/index.md` |
| `/en/services/`, `/it/services/` | `/en/services/index.md`, `/it/services/index.md` |
| `/blog/` | `/blog/index.md` (every post with title, date, author, reading time) |
| `/blog/<slug>/` | `/blog/<slug>/index.md` (MDX body, links absolutised, images resolved) |
| `/p/<alias>/` | `/p/<alias>/index.md` (markdown redirect to the article) |
| `/developers/`, `/contributors/`, `/database/`, `/database/<provider>/<title>/`, `/career-paths/`, `/career-paths/<path>/` | markdown redirect documents |

Variants are generated by `src/pages/**/index.md.ts` endpoints. Each document starts with
YAML frontmatter:

```markdown
---
title: "Orbis: Building a Modern Plugin-Driven Desktop Platform"
description: "An exploration of Orbis..."
url: "https://cyberpath-hq.com/blog/orbis-plugin-driven-desktop-platform/"
date: "2025-12-13T00:00:00.000Z"
author: "Emanuele (ebalo) Balsamo"
tags: ["rust", "react", "desktop", "architecture", "plugins"]
reading_time: "11 min read"
type: "article"
---
```

Redirect pages instead carry `redirect_url` and `redirect_status`, plus a body link, so an
agent does not have to execute a meta refresh.

`pnpm run check:markdown` fails the build when a generated HTML page has no markdown
variant, so coverage cannot silently regress.

## How the worker serves it

`worker/index.ts` is attached to **exactly two hostnames**:

| Route | Host |
| --- | --- |
| `cyberpath-hq.com/*` | apex / no-prefix |
| `www.cyberpath-hq.com/*` | www |

`workers_dev` and preview URLs are disabled, and the worker additionally checks
`url.hostname` against that allowlist, so a request for any other hostname (a later route, a
misconfigured custom domain) is forwarded untouched instead of being served a markdown
variant. `localhost` / `127.0.0.1` are allowed so `wrangler dev` works.

| Request | Result |
| --- | --- |
| `Accept: text/markdown` | `200`, `content-type: text/markdown; charset=utf-8` |
| `Accept: text/html`, browser headers, `*/*` | origin HTML, untouched |
| `text/markdown;q=0` | origin HTML |
| `Accept: text/markdown` + q lower than HTML q | origin HTML |
| assets (`/rss.xml`, `/favicon.svg`, `/assets/*`) | origin response, untouched |
| variant missing (404) | origin HTML |

Markdown responses carry `vary: accept`, `x-markdown-tokens` (estimated `chars / 4`) and
`x-markdown-source`. HTML responses get `vary: accept` added so shared caches keep the two
representations apart.

Full deployment details live in [worker/README.md](../worker/README.md).

## Deployment

1. Add repository secrets `CLOUDFLARE_API_TOKEN` (Workers Scripts: Edit + Workers Routes:
   Edit) and `CLOUDFLARE_ACCOUNT_ID`.
2. Check **Workers & Pages → Routes** for the zone first: Cloudflare runs one Worker per
   route. If another Worker already owns `cyberpath-hq.com/*`, merge instead of adding a
   second script.
3. Push to `master` (the `deploy-worker.yml` workflow deploys when `worker/` or the shared
   helpers change), or run `pnpm run worker:deploy`.
4. Purge the Cloudflare cache once, so cached HTML is not served for markdown requests.

## Verification

```bash
pnpm run build                  # generates the variants and validates coverage
pnpm run check:markdown         # same check, standalone
pnpm run check:markdown:remote  # fetches every URL with Accept: text/markdown
```

`check:markdown:remote` follows redirects and reports how many URLs were served directly
(`200`, the worker's behaviour) versus through a redirect (the fallback rule below), and it
verifies that a browser-like request still returns HTML.

Then audit the site:

```bash
curl -s https://isitagentready.com/api/scan \
  -H "Content-Type: application/json" \
  -d '{"url": "https://cyberpath-hq.com"}'
```

`checks.contentAccessibility.markdownNegotiation.status` should be `pass`.

## Alternatives (no Worker deployment)

**Markdown for Agents** (Pro / Business plans): AI Crawl Control → Markdown for Agents. The
edge converts HTML to markdown itself, capped at 6 MiB of HTML per response. Zero code; it
converts every page, including ones without a curated variant.

**Single Redirect rule** (any plan): Rules → Redirect Rules → Single Redirects.

```
any(http.request.headers["accept"][*] contains "text/markdown")
and not (http.request.uri.path contains ".")
```

Target (dynamic, 302, preserve query string):

```
concat("https://", http.host, regex_replace(http.request.uri.path, "/$", ""), "/index.md")
```

This is a redirect, not negotiation: the URL answers `302` instead of `200` with markdown,
`Vary: Accept` cannot be set, and strict scanners may still report a failure. Add a
response-header Transform Rule (`ends_with(http.request.uri.path, "/index.md")` →
`content-type: text/markdown; charset=utf-8`) if GitHub Pages does not send that type.

**Snippets**: the only dashboard-managed way to return `200` + `text/markdown` at the
original URL without a Worker deployment — still JavaScript at the edge.

## Recipes

```bash
# article as markdown
curl -sL https://cyberpath-hq.com/blog/orbis-plugin-driven-desktop-platform/ \
  -H "Accept: text/markdown"

# the markdown file directly (works with or without the worker)
curl -s https://cyberpath-hq.com/blog/orbis-plugin-driven-desktop-platform/index.md
```
